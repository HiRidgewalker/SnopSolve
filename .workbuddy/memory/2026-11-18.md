## 通读项目（场景 @scene#54「日常开发 / Development」，mode=coding）

项目：SnapSolve「秒解」，Android 拍照解题 / 作业批改 App，Java + CameraX + OkHttp，包名 `com.jone.snapsolve`，共 35 个文件（19 个 Java 类 + 12 个 XML + 2 个 .gradle + 2 个 properties）。统计已二次复核。

架构：端侧 CV（QuadDetector 亮面分割 + 凸包拟合四角 / contentRect 文字密度兜底 → QuadTracker EMA 稳帧 → 自动拍照）→ Perspective 单应矫正 → Sharpness 拉普拉斯方差拦糊 → 整页 JPEG 落盘 → VisionApi.solvePageStream 走 OpenAI 兼容 /chat/completions 的 SSE，逐行 JSON 吐题 → ResultActivity 追加卡片、按模型给的 y1/y2 画框 → 点击卡片懒加载 explain()。默认厂商为火山方舟（doubao-seed），对 volces.com 域名下发 `thinking:disabled`。

关键结论（供后续开发会话复用）：
- **P0 阻断**：缺 `app/build.gradle`、缺 gradle wrapper（`gradlew` / `gradle-wrapper.properties`）。settings.gradle 已 `include ':app'`，当前无法构建。依赖需补：AppCompat、CameraX（core/camera2/lifecycle/view）、OkHttp、Guava ListenableFuture。
- **P1 功能缺陷**：设置页的「提示词」`Prefs.prompt()` 仅被遗留方法 `VisionApi.solve()` 读取；主流程 `solvePageStream()` 使用内置 `solvePrompt()` / `gradingPrompt()`，用户改提示词不生效。
- `MainActivity.splitBtn` 名为切题、实为 `Prefs.grading()` 批改开关（布局初始文案 split_on 运行时即被 grade_on/off 覆盖；split_off 无引用）；`ResultActivity` 读入 `EXTRA_SPLIT` 后未使用；`Prefs.splitQuestions()` 定义了但 `QuadDetector.detect(..., false)` 硬编码 false。
- 复核确认的死代码：`ImageCompressor`、`ContentCropper`、`QuestionSegmenter` 零引用；`InkRows` 仅注释提及；`ResultActivity.sampleGray()` 未调用；`VisionApi.solve()` / `solvePage()` 为遗留路径。
- `coord()` 的 `"28%"` 分支实际未按百分制换算（剥掉 % 后 28 不满足 `d<1`，按 0-1000 原样返回）；`solvePageStream()` 无 catch，异常路径不回调 onDone，由 ResultActivity 的 catch 兜底。
- `UploadCache.get/put` 未接入，`MainActivity` 只用其 `sha256(path+size)`，且并非注释所称的内容哈希。
- 死代码：`ImageCompressor`、`ContentCropper`、`QuestionSegmenter` 零引用；`InkRows` 仅注释提及；`ResultActivity.sampleGray()` 未调用；`VisionApi.solve()` / `solvePage()` 为遗留路径。
- 安全：API Key 明文存 SharedPreferences；`usesCleartextTraffic=true` 且允许 http:// Base URL；MainActivity exported=true 且 `debugImage` extra 可绕过拍照直达结果页。
- 已知实现取舍（代码注释有据）：本地投影切题在密集排版上把「行」当「题」，已停用，改由模型返回 y1/y2 定位；`parseMarks()` 专门兼容模型流式输出的四种退化格式。
